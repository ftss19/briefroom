BRIEFROOM — SUBMISSION PLAYBOOK

POSITIONING
For account managers preparing for repeat customer meetings, BriefRoom recalls
what was promised, which objections changed, and how the contact prefers to meet.
Pitch: "Your next meeting should start where the last one ended."

WHY THIS FITS
The supplied problem statement explicitly lists Meeting Prep Agent (page 7).
Hindsight is mandatory. The initial public-search-only version was insufficient.
The upgraded live path uses Hindsight retain, recall, and reflect; offline
practice is a separate deterministic browser demo and does not satisfy the
mandatory Hindsight demonstration by itself.

JUDGING MAP
Innovation (30%): focus on changed objections and unconfirmed promises across
meetings, not a generic question-answer chatbot.
Hindsight memory (25%): show retention, restart/reload, recall, and reflection;
make the supporting facts visible. Show how a second outcome changes the brief.
Technical implementation (20%): separate provider boundary, typed validation,
per-account/contact banks, stable document IDs for retry, timeouts, evidence,
explicit failures, and automated tests.
User experience (15%): two dated fictional meetings, visible before/after,
export, and a trace the judge can inspect.
Real-world impact (10%): account managers avoid repeating resolved objections
and can verify commitments. No time-saving or revenue benchmarks measured yet.

3-MINUTE DEMO SCRIPT
0:00–0:20 — Introduce yourself and the problem.
"Before a repeat customer call, I need more than a company overview. I need to
know what we promised, what changed, and what this person cares about."
0:20–0:40 — Show the fixed no-history baseline.
"Without history, the preparation starts with generic discovery questions.
This baseline is a fixed illustration, not a measured competing AI run."
0:40–1:15 — Select Hindsight live. Load fictional meeting 1 and retain it.
"Anika needs security approval. We promised a questionnaire. She wants a short
summary. These are explicitly fictional notes for this demonstration."
Prepare with memory. Open the evidence and trace.
1:15–1:55 — Load fictional meeting 2 and retain it.
"Security is approved now. The remaining blocker is a ₹50,000 budget cap."
Prepare again. Check whether reflection incorporates this update. Do not read
an expected response as if it were the actual output.
1:55–2:20 — Refresh and prepare again with the same company/contact.
Show that live facts come back from Hindsight, not browser memory.
2:20–2:40 — Show evidence, export, and explain the architecture:
React -> FastAPI -> Hindsight retain / recall / reflect -> brief with evidence.
Tavily is an optional separate public-research tool.
2:40–3:00 — Close honestly.
"Memory changes what we prepare for. Next we need real user evaluation and
production access controls. We have not measured sales or time-saving gains."

SOCIAL DRAFT — REVIEW AFTER LIVE VALIDATION
A company summary cannot tell you what you promised last Tuesday.

We built BriefRoom around that missing context:
- Retain meeting outcomes in Hindsight agent memory.
- Recall objections and commitments for the same contact.
- Reflect on what changed before the next conversation.
- Inspect the evidence behind the brief.

The key test: when security is approved and budget becomes the blocker, does
the next brief change with it?
